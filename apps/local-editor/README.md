# PC内で動かすローカル編集版

**開発版。製品全体は未完成です。** API・編集操作・実MP4の合成試験は通過。
GitHubのUbuntu環境と実Chromeで、編集・書き出しと別保存先への素材再リンクの
合成素材による画面試験が成功しました。PR24はmainへ統合済みで、
[mainの実行40806270812](https://github.com/haji84/AI-VIDEO-STUDIO/actions/runs/40806270812)でも両経路と通常CIが成功しました。
iPhone/Android/Windows/Macの実機成功とは扱っていません。

## 起動

リポジトリを取得したPCで、Node、Python 3.11以上、FFmpeg/ffprobeが使える状態にします。
実測した環境は Linux / Node24.22.1 / Python3.12.14 / FFmpeg6.1.1です。
Windows/Macへの導入・動作は別途確認が必要です。追加課金・アカウント登録なし。

字幕を書き出す場合は、同じPythonへローカル描画用の依存を導入します。

```sh
python -m pip install -r requirements-media.txt
```

日本語を含む字幕には、その全文字が収録されたローカルフォントが必要です。
Windowsの既存日本語フォント、macOSのヒラギノ、LinuxのNoto CJKなどを探索します。
見つからない場合は `AIVS_CAPTION_FONT` に利用可能な `.ttf` / `.otf` / `.ttc`
の実在パスを指定してください（フォント集の0番目のfaceを使用）。このアプリが
フォントをダウンロード・インストール・再配布することはありません。
`CAPTION_FONT_GLYPHS_MISSING` は必要な文字が足りない状態です。欠字の四角を
成功扱いせず書き出しを止めます。字幕のない編集・書き出しはこの依存を使いません。

リポジトリのルートで実行します。保存先には**リポジトリの外にある専用の新しいフォルダ**を指定。ソースへの個人データ混入を防ぐため、リポジトリ内への保存は拒否します。

Windows PowerShell:

```powershell
node .\apps\local-editor\server.mjs --workspace "$env:USERPROFILE\AI_VIDEO_STUDIO_DATA"
```

Mac/Linux:

```sh
node apps/local-editor/server.mjs --workspace "$HOME/AI_VIDEO_STUDIO_DATA"
```

表示された `http://127.0.0.1:8765` を、そのPCのブラウザで開きます。
ポートが使用中なら起動時に `--port 8766` を追加。Pythonを別名で導入した場合は
`AIVS_PYTHON` に、その実行ファイルを指定します。

外部接続用のサーバーではありません。LANやインターネットには公開しません。
元動画は変更せず、選んだ素材を同じPCの専用フォルダへコピーします。容量が
不足する場合は読み込みを止めます。現在の上限は素材100本、1本16GiB/4時間、
書き出し音声クリップ64個。大容量素材の実測性能は未検証です。

## 操作

1. 「動画を追加」でMP4/MOVなどを選択。最初の映像をカットと元音声に配置。
2. 開始・使う長さ・速度・テロップを設定し「このカットを保存」。
   テロップの改行は保持され、長い行は実際の文字幅に合わせて折り返します。
   200文字以内でも表示領域に収まらないときは、文字を削除・縮小せずに停止します。
   その場合は字幕を短くするか改行数を減らしてください。
3. 再生位置で分割、前後へ移動、カット追加。「戻す・やり直す」で復元。
4. BGM・ナレーション音源・効果音を選択。最初は先頭へ配置します。
   「音源ごとの配置・フェード」で音源を選び、配置する開始/終了、素材から
   使う開始、速度、音量、繰り返し、フェードを入力し「この音声を保存」。
   「この音声を外す」はUndoで戻せます。4系統全体の音量/消音も独立しています。
   BGMは初期設定では全体へ繰り返します。音声生成は未対応です。
5. 「完成動画を作る」。完了後、実MP4を再生し「MP4を保存」。
   全編デコード、フレーム数、黒画面、無音、サンプル音量ピークとサンプル間ピーク（true peak）、静止・フリーズ候補とフレーム間隔の検査記録を保存できます。
   時刻が分かる要確認箇所は完成動画で再生し「このカットを編集」から戻れます。
   変更後に再作成すると新しいMP4と検査記録を作り、以前の出力を上書きしません。
6. 自動保存した編集は同じ保存フォルダで再起動すると再開できます。
   「プロジェクト保存」で別のJSONとして持ち出すこともできます。

追加カメラは素材として登録します。「複数カメラの同期候補」で基準と相手を選び、
「同期候補を調べる」。先頭の最大300秒をPC内で解析し、位置・一致度・一意性を
表示します。10秒以上の共通音声が必要で、無音・不確かなら確定できません。
「共通場面①」「②」で映像と音を確認し、チェックして「確認した候補を保存」。
解析だけでは編集内容を変えません。記録は再起動で復元し、編集後の古い候補は拒否。

「カメラ」を変えると確認済み同期位置から同じ場面の開始時刻へ合わせます。
確認前のカメラや撮影範囲外は警告します。手動の場合は「カメラ」で相手を選び、
同期位置と確認状態を保存してから選び直し、使用範囲を入力してください。
同期未確認なら書き出しを止めます。既に確認済みの値や選択音声は自動で変えません。
ドリフトは未測定で、非ゼロのドリフトはこの出力エンジンで未対応。画面分割GUIも
未対応です。推定値だけを実機の同期精度保証として使わないでください。

「自動編集の下書き候補」では、研修・記録・番組風・短編向けの傾向を選び、
「下書き候補を作る」。同期基準1本は位置0秒、他は確認済みの素材を使います。
確認済み最大8本、1本・共通区間とも20分以内、ドリフト0が現在の対象です。
明暗・動き・音量だけで選ぶ下書きで、内容理解や目標尺への要約は未対応です。
除外カメラと解析区間、各カットを確認し、素材ごとの再生で見直してください。
チェックして取り込むまで、映像カットは変わりません。古い候補や変更済み素材は拒否。
解析記録は再起動しても復元します。途中終了は中断、欠損・変更した記録は失敗表示。

取り込むと現在の映像カットを素材全体の候補で置換します。元音声・ナレーション・
BGM・効果音の素材、配置と音量は保持し、カメラの切替には自動追従しません。
音声と映像の関係は完成MP4で再確認してください。テロップ・効果・画面分割がある場合や、
候補が現在の音声より短い場合は、設定を保護するため取り込みを止めます。
適用後は通常の開始/長さ/テロップ編集、戻す・やり直す、保存・再開が使えます。
20分超の解析、意味の理解、役割・作業の正しさ、全品質保証は未対応です。

既存の複雑な字幕、配置、アニメーション等は勝手に単純化しません。対応して
いない編集は拒否し、元の設定を保持します。無音指定や独立した音声も保持。
アプリに連動していない音声が映像より長くなる編集は、保存できない場合があります。
音源の利用権は利用者が確認してください。内蔵楽曲・他社音声は同梱しません。

手動で配置・フェード等を変更した音源は、映像カットと独立した音声になります。
後から映像を切っても、その音声位置を勝手に変えません。映像より長くなる場合は
編集を拒否するため、音声の終了を先に短くしてください。元音声・他の音源の
選択は維持します。繰り返しは「素材から使う開始」から素材末尾の範囲です。
ダッキングを保存した音源は、その区間が範囲外になる変更を拒否します。
試聴は元素材です。ミックス/フェードの仕上がりは完成MP4で確認してください。
履歴操作で同じ編集対象を特定できなくなったときは未選択に戻します。
保存・削除する前に音源を選び直し、「編集中」の名前を確認してください。

黒画面・無音・静止画・可変フレーム間隔の検出は演出の可能性があるため、勝手に削除・修正しません。
意図的に選ばない音声や消音は区別します。旧出力の詳細検査は「未検査」と表示。
検査後に編集が変わった場合、古い検査記録から今のカットへの移動は拒否します。
`technical_ok` はデコード・時間・解像度等の技術条件です。`CHECKED_LIMITED`
でも字幕位置、音声の聞き取りやすさ、内容の妥当性、実機での再生品質、フリーズ等は
未検証です。1秒以上ほぼ変わらない映像を静止・フリーズ候補として表示します。
フレーム間隔は出力全体の変化数で、元動画からのフレーム欠落や原因までは判定しません。
古い検査記録は、実施していない新検査を未検査と表示します。
自動修復や全品質保証は未完成です。

サンプル間を含む音量ピーク（true peak）は推定値を0.1 dB刻みで表示します。
-1.0 dBTP以上を要確認の目安とし、音声を補正したり再生品質を保証したりする検査ではありません。
全編の最大値で発生時刻は特定していないため、「全編を確認」で再生し、必要なら音量を手動で編集して作り直してください。
この結果から特定カットの編集へは誘導しません。未計測・検査未完了・旧記録は「未検査」と表示し、測定できたデジタル無音とは区別します。

要確認の音量を調整するときは、完成動画を再生して音を確認し、「音源ごとの配置・フェード」で
調整する音源を選びます。「音量」を下げて「この音声を保存」し、再度「完成動画を作る」で
新しい検査結果を確認してください。戻す・やり直すと、保存後の再開が使えます。
合成音源のAPI検証では-6 dBの変更でピークが+2.6から-4.2 dBTPへ下がりましたが、
素材やミックスによって結果は変わります。一定の変更量で安全な音量になる保証はありません。
「以前の完成動画」で出力を選び「この出力を表示」を押すと、そのMP4と検査記録を確認できます。
現在の編集内容は変わりません。編集後の古い検査記録から、今のカットへの移動は拒否します。
履歴は最近50件です。対象から外れた古いMP4・検査記録も保存先から削除しません。
一覧表示では動画全件を読みません。選択したファイルの確認は、大きい動画では時間がかかります。
欠損・改変した出力や検査記録は開かず、エラーを表示します。

古い版の保存フォルダから復元できる履歴は、最後に完了した出力1件だけです。
完了記録のない、さらに古い出力は自動で一覧に追加しません。元のファイルは保存先に残ります。
追加の履歴保存だけに失敗した場合は、その旨を表示します。最新の完成動画の保存記録は保持します。
完成MP4の再生・保存と検査記録の照合、および保存プロジェクトのUndo/Redo復元は、
合成素材を使ったUbuntu上の実Chromeで検証済みです。「以前の完成動画」の一覧選択、
50件保持、欠損・改変・旧記録移行などの履歴機能全体はAPI試験の範囲であり、
その全分岐の実ブラウザ・各端末受入は未実施です。

### 保存したプロジェクトを別の保存先で開く

1. 「プロジェクト保存」で取り出したJSONと、編集に使った元の動画・音声を用意します。
   新しい専用フォルダを指定して起動し、「開く」でJSONを選んでください。
2. 不足している素材の種類・長さ・残り本数を表示します。「不足している素材を選ぶ」で
   元の動画・音声を選びます。複数ファイルをまとめて選択できます。
3. 素材がそろったら「このプロジェクトを開く」を押します。押すまでは現在の編集は
   変わりません。保存したカット・音量・戻す/やり直すの履歴を引き継ぎます。
   最後にプロジェクトを開いている間は、完了するまでキャンセルできません。

ファイル名が変わっていても内容が同じなら使えます。名前だけ同じ別素材や、変換・再圧縮した
素材は一致しないため使えません。履歴から戻せる素材も必要です。映像とBGMの両方に使った
同じMP4は、一度の選択でそれぞれの用途を復元できます。
今の保存先に確認済みの同じ素材があれば再利用します。

途中の素材で失敗しても、確認済みのコピーは残ります。アプリを再起動した場合はJSONを
もう一度選び、不足する素材だけを追加してください。キャンセル後も確認済みコピーは残り、
プロジェクトが自動で開くことはありません。別の画面で編集した場合は、画面を開き直し、
JSONを選び直してください。大きい素材の照合は時間がかかります。

保存JSONは4 MiB以下、履歴を含む素材と保存先の登録素材は100本までです。
同じ素材IDの内容が保存先と食い違う場合は上書きせず停止します。新しい専用フォルダを
使ってください。書き込み失敗の時点によっては未登録のコピーが保存先に残る場合があります。
そのファイルを自動で復元対象に加えることはありません。
元の動画・音声と保存JSONは保管してください。JSONには字幕なども含まれます。
この再接続は、Ubuntu上の実Chromeと二つの保存先で、合成素材を使って検証済みです。
誤った同名素材の拒否、途中再起動、明示的な「開く」、履歴・音量の復元、
実MP4の再生と全編デコードを確認しました。別PCへの移動・各実機での受入は未実施です。

## 保存したカットの映像・テロップを確認する

「素材を確認」は元動画の確認用です。保存した開始位置・長さ・速度・テロップの
仕上がりを確認するには、カットを保存してから「保存したカットを確認」を押します。
確認開始は、そのカットの完成後の秒数です。最大7秒を描画し、確認する範囲と
カット全体の長さを表示します。長いカットは開始位置を変えて続きを確認できます。
編集内容の保存前に自動で描画を始めることはありません。

保存した出力設定と完成動画用の描画処理を使います。確認動画には速度変更が
反映済みなので、再生速度を重ねて掛けません。映像と静止テロップの確認用で、
音声は初期状態で消音です。音楽・音量などの仕上がりは「完成動画」で確認してください。
この操作はプロジェクト・Undo/Redo・元素材・完成動画の履歴を変更しません。

現在はLinux環境に限って有効です。Windows/macOSでは、この新経路の子孫プロセス停止を
まだ検証していないため利用を止めます。既存の編集・書き出し機能とは別の制限です。
書き出し・同期・編集候補の処理と同時には実行しません。開始から180秒で期限となり、
確認動画も失効します。重い素材では期限内に終わらない場合があります。
カットの選択や保存内容が変わったとき、または素材・確認動画の一致を確かめられない
ときは、古い確認結果を表示せず、もう一度確認する必要があります。

停止処理は2秒以内に確認を試み、完了を確かめられない場合は新たな処理を始めません。
OSや保存装置の応答が止まった場合、その処理の完了まで保証できるものではありません。
強制SIGKILL・電源断などで親アプリ自体を止めた場合の子孫停止も保証しません。
強制終了後に確認用の作業データが残っている場合も、新しい確認処理を止めます。
アプリと子プロセスの終了を確認してから、保存先の確認用 `previews` フォルダだけを
退避または削除して再開してください。素材・プロジェクト・`exports` は残してください。

この候補を固定した時点では、新しい画面試験は実Chromeでの確認待ちです。
固定時点の実測と制限は `docs/validation/PREVIEW_PARITY_2026-10-29.md` に記録しています。
その後の実ブラウザ・main検証と統合結果は、この機能を含む実装PRと検証記録を参照してください。

## 終了・復旧

起動したターミナルでCtrl+C。通常のSIGTERMでも同じ終了処理を呼びます。進行中の書き出し・同期・下書き解析を待ってから終了します。保存済みカットの確認処理は停止を試みます。
異常終了後に `WORKSPACE_IN_USE` が出た場合は、同じ保存先のアプリが動いて
いないことを確認してから、保存フォルダの `.editor.lock` を削除して再起動。
処理中だった出力や解析は中断として表示し、新しいジョブで作り直します。

同じ保存先の二重起動は禁止。複数タブの古い変更は409で拒否し、最新状態を
読み直します。未保存の変更はJSONで取り出せます。保存済みの変更を黙って上書きしません。

## 検証

```sh
node --test apps/local-editor/*.test.mjs
node apps/local-editor/browser-acceptance.mjs
node apps/local-editor/browser-relink-acceptance.mjs
node apps/local-editor/browser-preview-acceptance.mjs
```

最初のコマンドはHTTP・実ファイル・FFmpeg・DOMスタブと編集・検査参照操作のテストです。
後の3つはPlaywrightと実ブラウザを使います。H.264/AACの完成動画を再生できる
既存Google Chromeの実在するパスを `AIVS_BROWSER_EXECUTABLE` に設定し、
`AIVS_PYTHON` にPython 3.11以上・Pillow 13の実行ファイル、`AIVS_CAPTION_FONT` に
日本語を表示できるフォントを指定します。ブラウザやPlaywrightがなければ `BLOCKED`、
終了コード2で停止します。このWork環境のブラウザ取得はHTMLエラーになったため、
同じダウンロードを繰り返していません。

`browser-acceptance.mjs` は合成映像の追加→手動同期確認→候補生成・個別プレビュー・
明示適用→字幕・トリム→Undo/Redo→JSON保存・再読込→音声配置・フェード→
実MP4再生・ダウンロード・全編デコードを操作します。

`browser-relink-acceptance.mjs` は別の一時保存先で保存JSONを選び、映像とBGMの両方に
使った同じMP4と、Redo履歴にだけ残したBGMを復元します。同名の誤った素材の拒否、
途中まで確認した素材の再起動後の再利用、明示的に「開く」を押すまでの編集保全、
Undo/Redo・音量編集・再起動、完成動画の実再生とBGM成分も確認する試験です。
ファイル選択・編集・保存・書き出しは実際の画面から行います。

既存 `manual-smoke.yml` の手動実行に、独立した `synthetic-browser-acceptance` ジョブを
追加しています。標準Ubuntu runnerのChromeを利用し、Playwright1.64.1、Node24.22.1、
Python3.12.14と試験用Python依存を固定します。両ジョブでFFmpeg/FFprobeを明示的に
導入し、コマンドの存在を確認します。ChromeとFFmpegの実際の版はログに残します。
