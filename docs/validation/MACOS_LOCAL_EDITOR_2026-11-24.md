2026-11-24 JST。Apple Silicon MacBook で `start-mac.command` を追加した実装
`80a38688062f5883548ce2699ed7020fdbbc98d4` を検証した。普段用の編集画面を起動し、
`~/AI_VIDEO_STUDIO_DATA` に空のプロジェクトを用意した。合成試験は別の専用フォルダで実施した。

## 起動と操作

1. Finder でリポジトリ直下の `start-mac.command` を開く。ターミナルが起動し、同じ Mac のブラウザに編集画面が開く。
2. 「動画を追加」で素材を選び、「自動編集の下書き候補」で「下書き候補を作る」。候補の再生と音声の保持を確認して「確認した下書きを編集へ取り込む」。
3. 字幕を付けるときは「テロップ」を入力して「このカットを保存」。次に「完成動画を作る」で出力し、再生して「MP4を保存」。
4. ターミナルで Control+C を押して終了する。次回も同じ起動ファイルから編集と完成動画を開ける。

既定の編集画面は `http://127.0.0.1:8765/`。別の専用フォルダで試す場合は、
リポジトリ直下で次を実行する。

```sh
./start-mac.command --workspace "$HOME/AI_VIDEO_STUDIO_TEST" --port 8766
```

開発機の標準 PATH だけでは Homebrew のツールが検出できず、Homebrew の FFmpeg 8.0 には
マルチチャンネル音量検査の既知の問題があった。前回検証した 8.0.3 を Mac のアプリ専用
フォルダに保存し、ランチャーから使用した。字幕の依存はリポジトリの `.venv`、フォントは
macOS 標準のヒラギノ角ゴシック W3 を使った。起動先と構成は他の Mac でも指定できる。

## 検証結果

- macOS 26.6.2、Node 24.21.0、Python 3.14.7、Chrome 157.0.8103.79、FFmpeg／ffprobe 8.0.3。
- 標準システム PATH とリポジトリ外の作業ディレクトリから起動し、日本語と空白を含む保存先で `127.0.0.1` のみ待受を確認した。Finder と同じ `.command` をターミナルで開き、普段用の空のプロジェクトを確認した。
- 通常の画面で日本語ファイル名の合成素材1本を追加した。自動編集候補を再生・適用し、日本語字幕と元音声付き H.264/AAC を出力した。字幕は12種類の文字の収録を確認した。出力は 960×540、4.02002秒、96フレーム、471,564バイト。初回・再起動後に全編再生し、MP4 の SHA-256 が一致した。全編デコードを通し、元ファイルと再起動後の保存プロジェクトの SHA-256 も確認した。
- 同じ FFmpeg／ffprobe と標準フォントで、合成2本の検査失敗、再送なしの取り込み、自動編集候補の適用、全編デコードと再起動後の再生も成功した。
- Node 187件が成功、Linux 専用の10件をスキップ。Python 69件と音声3件が成功し、DejaVu Sans 固定の字幕テストクラス1件をスキップした。
