## Design and scope

Use existing project v1, EditSession, protected HTTP edit API and actual renderer.
`audio-edits.mjs` supplies read-only-input project operations, used by the real
`audio-panel.mjs` UI. Start/end, source trim, speed, gain, loop and fades are
explicit. Removal is explicit and undoable. No new synthesis/model/dependency.
Other media, custom IDs, ducking and audio selection are preserved. Invalid
source/output/fade/ducking ranges are refused instead of silently clamped.

Decision: manually editing an app-generated source/BGM slot makes it independent
by assigning a collision-free short audio_manual_N ID. This prevents subsequent
video trim/automatic BGM resize from overwriting explicit audio timing. Existing
custom IDs stay intact. No-op saves retain IDs. IDs are project-internal; project
revision invalidates old output finding navigation. UI/guide explains independent
timing. A shortened video can require trimming the separate audio first.

lost after Undo/Redo and fell back to original audio, allowing accidental removal
without visible selection. A real UI-module DOM-stub test reproduced deletion
(RED). Fix: never guess a replacement after selection is lost; hide save/remove
until explicit reselection, and show a clear border plus current source/bus name.
