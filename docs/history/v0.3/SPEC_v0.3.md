# AI VIDEO STUDIO v0.3 正式仕様草案

更新：2026-10-21
状態：**設計版 / 未実装・未実機検証の機能あり**
目的：CapCut並みに使いやすい「ローカル優先」の動画編集アプリに、目的別AI編集・複数カメラ・日本語AI音声・仕上がり検査を組み合わせる。

## 1. 決定事項・製品境界

1. AI VIDEO STUDIOとGORIQは**別製品・別リポジトリ・別の完成判定**とする。将来、明示的なAPIと許可によりGORIQに開発・保守依頼を送ることは可能。動画や個人情報の自動共有は禁止。
2. **端末内編集・端末内保存・オフライン動作を標準**とし、クラウド解析／レンダリング／バックアップは任意・費用見積と個別同意を必須とする。R2加入・契約・一般公開は今回の対象外。
3. iPhone・Android・Windows・Macに展開。iOS/Androidはネイティブ処理を優先、共有エンジンの仕様と保存形式は共通化する。既存Web v0.2.1は研究・プロトタイプ資産であり、端末内の重い処理をすべてそのままWeb移植できるとは限らない。
4. 元動画のバイト列を変更しない**非破壊編集**。完成MP4と別に再編集可能なプロジェクトを保存する。OS権限失効・元動画移動時は再リンクUIを提供。
5. 動画数に固定的な2本制限は設けない。1本・2本・3本以上を設計対象にする。ただし同時デコード・解析数には機種ごとの安全な制限があり、プロキシ生成や順次処理で対応する。
6. 編集前に動画の種類・目的（教材、ドキュメンタリー、テレビ風、ショートなど）を選ぶ。完成尺は固定しない。重要工程・時系列を最優先に残す。
7. 会員登録・Stripe・一般公開・サブスク事業化は**後日**。商用の素材・音声・モデルライセンスは将来の配布前に独立検査する。

## 2. 利用者体験

### A：全自動モード
動画を選択（複数選択／ファイルアプリから追加）→目的と任意の役割を設定→「AI編集」→端末内の軽量解析→候補タイムライン作成→効果・字幕・音声を自動配置→プレビュー→ローカル書き出し→自動品質検査→問題があれば修正候補作成→完成。端末の電源・OS制限で停止する場合は、**チェックポイントから再開**。停止中も作業していたと偽らない。

### B：かんたん手動モード
編集画面は「追加」「カット」「テロップ」「エフェクト」「AI音声」「カメラ切替」「戻す」「完成」の大きなボタンを基本とする。1タップのプリセット適用→短い実映像プレビュー→強さ・長さをスライダー調整→必要なら詳細設定、という段階開示。

初心者は編集の専門用語を覚えなくても「この場面を3秒短く」「別角度に」「動きをゆっくり」「ここにナレーション」の日本語命令でも操作できるようにする。命令の解釈モデルが未搭載なら基本メニュー操作に戻す。プレビュー、Undo/Redo、操作履歴、比較表示、テンプレートお気に入りを必須とする。

### 画面の主領域
上部：映像プレビュー／切替前後比較。下部：タッチしやすいタイムライン、動画・音声・字幕・エフェクトのレーン。横に初心者用ツールタブ。スマホ縦持ちでも操作でき、横持ちでタイムライン拡大表示。カメラ1〜Nの同期レーンを表示。

## 3. 端末内AI解析の階層

**L0 確実性の高い信号・数値処理（AI不要）**
- 動画メタデータ（長さ、解像度、FPS、コーデック、音声、撮影情報）を調べる。
- 音声波形、無音・ピーク・粗いノイズ指標、映像の明暗、黒画面・欠落フレーム候補、シーン変化を検出。
- 2台以上の音声相関や時刻メタデータで同期位置を推定し、信頼度と誤差範囲を表示。共通音声がない場合は映像ランドマーク／手動同期へ。

**L1 軽量ローカルAI（端末ごとの適合性を実測）**
- 日本語音声の書き起こし、字幕の時間合わせ、言いよどみの候補検出。Whisper.cppまたはOSの端末内音声認識を検証する。
- 人・姿勢・物体の検出、顔領域の追跡、被写体中心にリフレーミング。Apple VisionやMediaPipeを使用候補とする。
- 音と動きの変化から重要場面候補をランキング。ただし専門的な「正しい動作」「役割」は自動確定しない。

**L2 高度な意味解析（実測次第）**
- 行動の意味、役割、作業の進捗、重要判断、長時間文脈を解析。
- 日本語音声台本を提案し、技術解説の根拠がどの映像時刻か示す。
- 端末内で実用的な精度と処理時間を満たせなければ、音声＋代表フレームだけを**利用者同意のうえ**クラウドへ送る選択肢を表示。勝手に送信しない。
- 専門知識による安全・技術評価は参照資料や人の確認なしに断言せず「要確認」へ。

## 4. マルチカメラ・Insta360

- 各素材に独立したsourceIdを与え、映像のローカル時刻を共有の訓練時刻へマッピング。オフセット、ドリフト、手動基準点を保存。
- N台のカメラを連携し、優先視点、2分割／3分割、画面内小窓、スロー、カメラ切替の理由と証拠時刻を保存。
- MP4かつ360度エクイレクタングラーであれば視点変換を検討。INSV独自コンテナは直接読めると断定しない。必要に応じInsta360 Studioなどの認可された変換方法で元データを保持。
- 編集対象の尺はタイムラインの活動長／ユーザーの好みに応じて決める。20分撮影を機械的に20分へ再構成しない。

## 5. テロップ・テキストエフェクト

- **ワンタッププリセット**：フェード、スライド、ポップ、弾む、タイプライター、ワイプ、キラッ、グリッチ、カラオケ字幕、強調単語、下三分の一ラベル、吹き出し、人物追従ラベル、図解矢印。
- すべてのプリセットは `effectId/version/parameters/start/end/keyframes` の共通データ定義から描画。画面で見た演出をMP4でも同じ時刻に再現できる検証を必須とする。
- 文字の読みやすさ：輪郭・背景帯・縁取り・影・色・表示時間。字幕と図解を混同しない。小画面でも読めるフォントと安全な表示領域。
- 字幕からのナレーション化や音声からの自動字幕生成をワンタップ化。誤変換は編集可能。
- 無料プリセットを最初から提供し、将来の追加素材マーケットと完全に分離。CapCutの素材そのものは無断取得・再配布しない。

## 6. 動画エフェクト

- **基本**：露出、ホワイトバランス、彩度、コントラスト、モノクロ、シネマ調、ビネット、ぼかし、シャープ、クロップ、ズーム、パン、回転。
- **本格演出**：グリッチ、色ずれ、ズームトランジション、速度ランプ、モーションブラー、手ぶれ補正、顔モザイク、自動リフレーム、複数画面、キーフレーム。
- **教材テンプレート**：手元強調、動線矢印、停止・スロー比較、複数カメラ比較、経過時間／役割札、確認ポイント枠。
- 素材と出力解像度、端末性能によってプレビュー画質を動的に調整。最終書き出しは元動画の解像度を考慮する。
- 効果はタイムラインデータとして非破壊保存。保存後も強度・時刻・順序を編集可能。

## 7. AI音声・ナレーション

### 機能要件
テキスト入力→日本語の声を一覧試聴→速さ・ピッチ・間・音量の調整→台本の難読語登録→音声生成→自動でタイムライン配置。文章の一部だけ修正した場合、変更部分だけ再生成。発音辞書・フレーズごとの手動調整・間の調整・字幕同期・BGMの自動ダッキングを用意。

### ローカル音声モデルの優先順
1. **OS標準の読み上げ**：iOS AVSpeechSynthesizer の端末内で利用可能な声、Android TTSエンジンのオフライン音声を検出し、サンプルを書き出して実測。端末や声によって品質やオフライン可否が異なる。
2. **追加ローカルモデル**：Kokoro-82M（v1.0の日本語対応・重みApache-2.0は確認済み）等を候補とし、iOS/Androidへの推論実装、自然さ、メモリと配布物のライセンスを検証する。モデルの実機搭載は未完了。
3. **PC向け任意音声**：VOICEVOX/VOICEVOX Nemoを導入候補とし、ユーザーごとの声の利用規約・クレジット表記を適用。公式PC版がそのままスマホで動くとは扱わない。
4. **クラウド音声**：上記で満足できない場合のみ任意のプロバイダを選択。費用見積・明示承認・音声素材の送信範囲を表示。

**CapCutとの違い**：CapCutと同じ「文章入力→声を選択→生成→動画へ挿入」という操作感を目指す。CapCut固有の音声モデル・声優の声そのもののコピーはライセンス確認なしに行わない。自分の声のクローン機能は将来の選択式とし、本人または権利者の明示同意と悪用対策が必要。

## 8. 技術アーキテクチャ

```text
iPhone Native (SwiftUI + AVFoundation + Vision + Core ML + Audio)
Android Native (Compose + Media3 Transformer + MediaPipe + TTS)
Windows / Mac (existing FFmpeg engine + accessible desktop UI)
    |
    v
Shared Project Schema + Source Reference + Timeline + Effect Pack
    |
    +-- Local Analysis Engine (metadata/scene/sync/ASR/vision)
    +-- Local Render Engine (device codec/GPU or desktop FFmpeg)
    +-- Local TTS (OS voice or packaged model)
    +-- Local technical QA + resumable checkpoints
    |
    +-- Optional Cloud Adapter (separate consent/cost gate)

Separate future integration: GORIQ developer API (no media exfiltration)
```

v0.2.1の `engine/core_v01.py`, `engine/run_manifest.py`, UI/API, project timeline ideas は再利用候補。クラウド必須前提を共通インターフェースで置換し、端末別アダプターを作る。既存パッケージを破壊せず独立ブランチで改修。

### 保存形式
`projectVersion, projectId, sourceRefs[{assetId,hash,deviceBookmark,metadata,offset}], timeline[{clipId,sourceId,trim,speed,layout,effects[],text[],narration[]}], syncAnchors, modelUsage, privacyConsent, exportProfiles, history`。移行スキーマと後方互換試験を必須にする。個人情報や秘密の音声はプロジェクトに平文で混入させない。

## 9. 自動品質検査と修正ループ

- 技術的QA：解像度、再生可能性、音量ピーク、無音、黒画面、フレーム欠落、字幕の画面外逸脱、音声とテロップの時刻ズレ。
- 意味的QA：本当に重要場面を残したか、説明が映像と一致するか、台本に根拠があるかはAI評価＋根拠時刻＋不確実性。AI自身の判定だけで専門的正確性PASSにしない。
- 重大な技術不良は変更範囲を限定して再編集し、再レンダリング・再検査。ループ回数・電池・発熱・ディスク容量上限を設ける。
- 元映像と品質証拠を保持し、出力物のハッシュを保存する。

## 10. 非機能・安全性・コスト

- 原本非破壊、オフライン優先、保存場所とクラウド送信の明確化。
- モバイルではメモリ圧力、ディスク空き容量、バッテリー、温度、OSバックグラウンド制約に応じて停止・縮退・再開する。**スマホを閉じても常に処理継続する保証はしない**。
- カメラ数／映像サイズ／解像度／利用可能な物理メモリで能力ランクを分け、端末の限界以上の編集を要求しない。
- クラウド選択時は事前見積と明示承認、月額目標500〜1000円は費用管理目標であり厳密な上限制御とは区別する。
- 顔・声・個人情報を含む動画の取扱いには権利・許可の確認を設ける。
- 追加モデル／声／エフェクト素材のライセンスと帰属表示を逐一記録する。

## 11. 優先開発順

P0-1. 実機能力計測。iPhoneでブラウザ事前チェック後、ネイティブ小規模試作で解析・TTS・10分1080p書き出しを計測。AndroidとPCは続けて独立計測。
P0-2. 共通プロジェクト保存形式・移行・非破壊編集・復旧。
P0-3. テロップ・動画エフェクト各5種、プリセットUI、ライブプレビュー、ローカルMP4書き出し。
P0-4. OS内蔵TTS（日本語）の試聴・調整・音声保存・タイムライン配置。
P1-1. 音声同期・ASR字幕・カメラN本・AIカット候補。できないことは明示して手動補正へ。
P1-2. モバイルローカル音声モデルの比較と効果パック拡充、初心者テスト。
P1-3. 全編技術QA／再編集、目的別AI構成、意味的QAの根拠照合。
P2. 任意クラウド拡張／原価実測。
保留. サブスク／一般公開／GORIQ連携の実稼働。

## 12. 完成定義（DoD）

1. iPhone/Android/PCごとの実測表に、動画形式、処理時間、最大メモリ、発熱、電池、AI精度、書き出し成否が残る。
2. 動画1・2・3本以上を同期し、異なる撮影開始時刻と無音を処理できる。音声が合致しないときは誤同期で通さない。
3. テロップ／動画エフェクト／ナレーションを選択、プレビュー、調整、保存、再編集しても変化が失われない。
4. 「クラウド禁止」の状態でローカル編集・書き出しができ、通信ログから無断送信がないことを確認。
5. 約11GBの実素材は端末に存在する場合のみ試験し、実物にアクセスできないときは未検証と記す。
6. 完成MP4全編の技術検査を行い、専門判断は要確認を許す。サンプルのみで全編検証済みとは言わない。
7. 端末再起動や容量不足での中断後に、原本と編集プロジェクトを保護し再開できる。
8. 商用販売に進む前にすべての音声・画像・エフェクト・AIモデル・配布ライセンスとプライバシーを検査。

## 13. 判定のルール

**確認済み**は公開API/ソースの存在だけ。**端末実証済み**は利用者の実機で処理を行い計測結果を保存できた場合のみ付ける。
確認済みのAPIが存在しても、モデルの編集精度・端末速度・すべての機種での対応は別評価。現時点ではiPhone/Android実機での正式E2Eはまだ一件もPASSとしていない。
